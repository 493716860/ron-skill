# 营销活动前端规范（强制）

## 范围与职责
小程序负责展示和用户交互；运营后台负责活动创建、审核、配置、发布、暂停、结束与统计；后端负责资格、库存、价格、订单和状态的最终判定。

## 限时秒杀
支持秒杀专区、活动列表/详情、开始/结束倒计时、限购提示、活动价、库存状态和抢购。倒计时以服务端时间为基准并校准客户端偏差；倒计时结束不代表服务端一定允许购买。提交订单前必须通过服务端活动资格、库存和限购校验；防止按钮连点导致重复提交。

## 拼团
支持拼团列表、商品详情、开团、参团、团成员与剩余人数、待成团/成功/失败/取消状态、订单详情与退款进度。团状态和成团人数由服务端返回，前端不能自行宣布成团；超时失败和退款状态须查询后端。

## 活动价及优惠
支持活动价、会员专享、新人专享、优惠券、满减满折、专题专区与活动入口。统一展示原价、优惠信息和服务端报价；活动价与会员折扣、积分、优惠券的叠加关系必须遵循后端价格引擎和业务决策表。不得前端自行计算实际应付金额或猜测叠加优先级。

## 页面状态
覆盖未开始、进行中、已结束、已售罄、资格不足、活动下架、弱网、价格变化、库存变化、支付失败、拼团失败退款等状态；错误提示应指导用户重新获取有效报价。活动入口可由首页装修配置，跳转仅允许白名单页面。

## 数据与类型
营销 API 类型需定义活动 ID、活动类型、开始/结束时间、活动状态、价格展示、购买限制、服务端时间、优惠适用条件、拼团 ID 等必要字段；具体字段以实际后端契约为准，不得杜撰接口。营销倒计时与实时库存展示不能替代服务端交易校验。

## 成本控制
不强制接入实时推送、消息队列、复杂营销规则引擎或额外状态管理框架。优先请求查询和按需刷新，涉及高并发营销由后端保证原子库存与幂等。
